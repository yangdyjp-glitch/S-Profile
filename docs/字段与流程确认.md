# S-Profile 字段与流程确认

> 版本：1.0｜确认日期：2026-11-25（日本时间）
>
> 本文取代此前的待确认草案。业务依据为逐项确认结果及用户批准的《S-Profile 第一版实施计划》。
> 配套实现设计见 [系统架构设计.md](./系统架构设计.md)。旧 Excel 中的文字、下拉和格式是迁移来源，不自动构成网站规则。

## 1. 记录单位与共同规则

1. 一名学生一个永久档案；一名学生可以有多次服务。
2. 主列表一行一次服务，按进行中、暂停中、出愿中、已完成查看。
3. 每次服务可以有多个合同项目和多条学校申请，但只有一个主阶段。
4. 进入出愿阶段后，原有材料、教授联系等工作继续保留和维护。
5. 常规进度、出愿情况都属于学生，不区分服务，两者分别显示。
6. 修改保留旧值、操作人和时间；跨阶段不删除资料和记录。
7. 新建执行必填规则。历史导入的缺失信息保留真实空值并标记待补。
8. 业务字段、网站登录账号和原始导入资料分开管理。

## 2. 学生档案字段

| 字段 | 含义与取值 | 必填与变更规则 |
|---|---|---|
| 学生姓名 | 保留姓名中的星号、别名、读音说明和原显示文字 | 必填。查重忽略星号和空白；不得重复建同名档案。更名同步所有服务，旧名留存 |
| 签单时间 | 我方首次接受该学生渠道订单的年月 | 必填。所有服务共用学生首次接单月份，不另记每次服务的签单月份 |
| 掌握语言 | 已取得的 JLPT、托福、雅思、托业结果 | 必须明确已有成绩或暂无语言成绩；不要求考试日期，不记录备考安排 |
| JLPT | N1合格、N2合格、N3合格、N4合格、N5合格、暂无日语成绩 | 有结果时选择对应等级；不新增日语考试日期或分数字段 |
| 托福／雅思／托业 | 各自的数值成绩 | 采用每种考试最近录入或更新的结果，旧值保留；不自动改语言风险 |
| 学生管理 | 一名学生的一位当前学管 | 选填，空值显示学管待分配。更换后全部服务显示当前学管；历史经办和奖励归属保留 |
| 所在地 | 当前居住地：中国、日本、欧美 | 必填；全部服务共享，变更留痕 |

星号是临时视觉标记，没有固定业务意义。学生身份由稳定内部编号关联，姓名是显示和查重字段。

## 3. 服务字段

### 3.1 基础与合同

| 字段 | 含义与取值 | 必填与关系 |
|---|---|---|
| 甲方 | 提供学生的渠道机构，不一定是合同签约方 | 必填、单选；从名册选择，可现场新增；没有直客业务 |
| 申请项目 | 合同约定的服务项目 | 必填、多选；可新增类型。修改仍属于本次服务，保留旧项目和已有学校、工作、记录 |
| 专业方向 | 本次服务目标专业，自由文字，可写多个方向 | 必填；不是学生原专业；本次服务所有项目共享 |
| 教务老师 | 本次服务的一位教务 | 选填，空值显示教务待分配；不同服务可以不同；交接留痕 |
| 原合同入学目标 | 最初约定的一个或多个入学年月 | 至少一个，只允许4月或10月；保留原值 |
| 当前入学目标 | 本次服务当前采用的目标年月 | 当期显示原合同时间，延期显示最新目标；所有合同项目共享 |
| 特记事项 | 本次服务的特殊要求和注意事项 | 选填 |
| 备注 | 本次服务的其他补充说明 | 选填，与特记事项分别保存 |

甲方变化只影响本次服务，不自动更改其他字段。

### 3.2 学生状况

| 取值 | 判定 |
|---|---|
| 未开始 | 材料可以已收集、制作，但尚未开始联系教授或正式申请 |
| 当期申请 | 按原合同约定目标申请，与当前日历年份无关 |
| 延期 | 判断不能实现原合同目标，需要更晚的目标；标记时必须填写新目标 |
| 暂停中 | 当前服务暂停，与暂停阶段同步 |

新建时明确选择，不设置普通状况默认值。状态由工作人员判断，不按日期自动推算。

- 原合同允许多个批次，仍可达到其中任意一个时不算延期。
- 补签协议后仍保留延期判断，不能用新协议覆盖原目标并自动恢复当期。
- 暂停前的状况保留，恢复时重新选择。

### 3.3 材料与工作进度

| 字段 | 范围与取值 | 填写规则 |
|---|---|---|
| 材料准备情况 | 学生提供的基础材料；尚未收集、收集中、收集完成 | 服务统一记录，必填、手动选择、不设默认；补材料时可退回收集中 |
| 材料制作 | 联系教授使用的简历、邮件、研究计划等；尚未制作、制作中、制作完成 | 服务统一记录，必填、手动选择、不设默认；材料可用于申请即为完成，可退回制作中 |
| 申请进度 | 整次服务的整体进度，八项单选 | 必填、手动选择、不设默认，不自动切换服务阶段 |
| 出愿材料 | 学校公开发布本批次出愿信息；未发布、已发布 | 服务统一记录，默认未发布；至少一所拟出愿学校公开信息即可手动标记已发布 |

材料收集、制作可以并行；材料未全部制作完成也允许给教授发邮件。“出愿材料”不表示我方发材料清单或已经递交申请。

| 申请进度 | 含义 |
|---|---|
| 未开始 | 尚未开始实际申请工作 |
| 发邮件中 | 已实际发出联系教授的邮件，包括继续发送和等待回复 |
| 研究计划 | 正在制作或修改计划书，不要求已经联系教授 |
| 拿到内诺 | 至少一位教授明确愿意接收 |
| 出愿中 | 开始准备正式出愿材料，包含递交、考试和等待结果 |
| 出现问题 | 问题已影响正常推进 |
| 完成申请 | 任意一所学校正式合格即可，其他申请可以继续 |
| 确定退款 | 已确认退款决定，款项可以尚未退完 |

实际申请已经开始而学生状况仍为未开始时，要求改选当期申请或延期。研究计划制作、出现问题、退款决定本身不自动证明已经开始联系教授或正式申请。

### 3.4 申请风险

风险必填、单选、不设默认，由工作人员选择当前最主要的一项。

| 取值 | 含义 |
|---|---|
| 语言风险 | 成绩或实际沟通等语言水平可能影响申请 |
| 配合风险 | 学生回复、材料提交、约定任务等配合不足 |
| 目标风险 | 目标学校或要求高于学生现有条件 |
| 时间风险 | 剩余时间不足以完成申请目标 |
| 退款风险 | 尚未确定退款，但存在退款可能 |
| 方向风险 | 方向匹配、机会不足，或方向不明确、频繁变化 |
| 暂无风险 | 当前未判断出上述风险 |

风险不自动更改申请进度或阶段，也不由语言成绩自动推导。

## 4. 学校申请字段

只登记已实际递交的申请；准备中的学校先在出愿情况中记录。进入出愿阶段可以暂时没有学校记录。

| 字段 | 规则 |
|---|---|
| 学校名称 | 自由输入触发联想，选择已有学校；没有匹配项可以新增 |
| 申请记录 | 归属一次服务；同校不同项目或批次分开，不限三所 |
| 实际项目类型 | 必填，使用统一项目名册；可与合同项目不同，不回写合同 |
| 具体项目名称 | 研究科、课程、项目名称，自由文字，选填 |
| 学校入学时间 | 该学校实际申请批次，年月只允许4月或10月，可待定；与合同目标独立，不做比较或提醒 |
| 出愿截止日期 | 只记录截止日，不记录开始日；可待定；学校列表按截止日先后排列，待定置后 |
| 出愿工作月份 | 开始办理这条申请的年月，选填；跨月填开始月份，不是实际递交日或截止日 |
| 合格时间 | 我们实际收到合格消息的年月日；每条学校申请分别记录，新增合格结果时必填 |
| 最终选择 | 可以选择多条合格学校申请，未选择的合格结果仍保留 |
| 内诺时间 | 最终选择学校对应的内诺年月；由老师判断是否需要内诺，需要则必填；多条最终选择分别维护 |

内诺指教授明确愿意接收，不是一般积极回复，也不以学生接受的日期为准。移除学校记录时保留历史。

## 5. 两类学生记录

| 项目 | 规则 |
|---|---|
| 归属 | 学生级，不按服务拆分 |
| 分类 | 常规进度、出愿情况，分别设区域 |
| 内容 | 每次新增一条自由文字 |
| 日期 | 默认当天，允许补记过去日期；真实录入时间另存 |
| 修改与作废 | 有档案编辑权限的人可操作，原文、版本、操作人、时间全部保留 |
| 展示 | 列表显示最新记录；详情倒序查看全部历史，支持按年月筛选 |
| 出愿情况必填 | 允许为空 |
| 旧记录 | 日期明确时按条拆分，正文省去与业务日期相同的开头日期。日期待核时也清除每行开头带冒号的日期标签，保留正文中的业务时间。核对时可查看原表日期列和单元格原文 |

## 6. 阶段流转与完成情况

| 操作 | 规则 |
|---|---|
| 新建 | 默认进行中；补录可选择实际阶段 |
| 暂停 | 只有进行中可以暂停；全部常规服务工作停止，仅处理恢复、退款等必要事项 |
| 暂停原因 | 每次暂停分别保存，允许为空 |
| 恢复 | 默认原阶段、可调整；重新选择学生状况；原工作保留 |
| 出愿后退回 | 可以回到进行中，保留学校、记录和阶段历史 |
| 正常再次办理 | 已完成服务保持完成，另建新服务 |
| 误结案撤回 | 所有成员可直接撤回，无需填写原因；保存结案、撤回及操作人历史 |
| 尾款 | 未收齐也可以结案，继续在备注中记录 |

完成情况只选择一种：

| 类型 | 条件与说明 |
|---|---|
| 学校结果 | 至少一所正式合格；无需等最终选校确定；展示全部合格学校与项目 |
| 退款 | 约定应退款全部退完；自由文字退款说明必填，不拆金额、币种、日期 |
| 学生放弃 | 学生或渠道明确终止且不退款；放弃原因选填；临时不回复、犹豫或暂停不直接算放弃 |
| 服务结束（已结单） | 其他已确认不再继续服务的情况，如指导交付、到期或约定结束；说明选填 |

完成页的“申请时间”是结案时最新入学目标快照；“项目”是合同项目。教务、学管显示当前分配人员，历史经办保留。

## 7. 奖励结算

- 每次服务一份，教务和学管分别记录归属人及结算年月。
- 结算年月指计入哪一期工资，而不是实际付款月份。
- 归属人默认当前负责人，可调整确认；已确认归属不随人员交接改变。
- 不增加奖励状态、金额字段；空月份仅表示未填写。
- 奖励未结算不阻止服务结案。
- 原表关于合格数、绩效奖励的文字保留为历史说明，第一版不据此自动计算。

## 10. 权限、迁移与导出

### 10.1 权限

- 内部团队使用；普通自定义用户名和密码，不要求 ChatGPT 账号。
- 管理员创建账号，不开放自行注册；显示姓名与登录名分开。
- 全员可查看、修改全部业务资料；账号管理由管理员负责。
- 登录页面可互联网访问；资料、原文件、历史和导出需要内部账号登录。

### 10.2 迁移

- 四张表全部迁入，包括隐藏行；保留原工作簿、坐标、原文和格式。
- 历史缺失允许为空，标记待补；不补造日期、成绩。
- 同名跨表仅提出匹配建议，由人工确认是否同一学生、同一次服务。
- 重复、错位、日期冲突、跨学生合并单元格等在网站核对页分批处理。
- 明确的数据先使用；相同来源再次导入不得重复生成业务记录。

### 10.3 导出

- 支持当前筛选列表和完整资料导出 Excel。
- 两类记录分别按学生汇总，完整年月为列，同月多条记录放在对应月份。
- 日期不明的原文单独保留；长文本超过单元格容量时续行，不截断。
- 第一版提供记录、筛选和导出，不建设专门统计页面。

## 11. 业务规则与技术设计的边界

本文是业务规则基线。数据表、接口名称、事务策略、页面布局、首个管理员初始化等技术设计由配套架构文档定义。
历史数据中尚待核实的是具体旧记录的含义和归属，不代表本文件中的业务字段仍待确认。
